## 〇、术语表（先看这一节，后面所有缩写都在这里）

| 术语 | 全称 | 一句话解释 |
|---|---|---|
| 产品 / 板 | — | 一张待检的图片＝一个产品（一块板）。本文中"产品""板""图"同义。 |
| 焊座 | pad / land | 芯片上用来接受飞线的**焊点位置**，是印刷电路裸露金属的部分，图上表现为**亮色方块**。 |
| 焊点 | solder joint | 飞线与焊座**连接**的地方。因为有焊锡，图上表现为**黑色圆斑**。判定用的"焊点"就是这一处连接。 |
| 焊盘 | pad | 口语中对"焊座/焊点"的笼统说法；本项目中凡涉及判定，一律用"焊座"或"焊点"两个准确说法。 |
| 裸焊盘 | bare pad | 焊座上原本有焊点的位置，飞线断掉后只剩一团**黑色焊接印记（焊锡）**。 |
| 飞线 | wire / jumper | 两个焊点之间连着的那根细线。合格产品上每根飞线连接两个焊点。 |
| 断联 | disconnection | 本该连到焊点上的飞线没接上（悬空或差一点点）。 |
| 弯曲不合格 | bend defect | 飞线走向弯折过度，超出允许范围。 |
| 裸焊盘 | bare pad | 焊盘裸露，上面**没有**飞线。 |
| 候选点 | candidate point | 由图像处理先粗挑出来的"可能是焊点"的位置。 |
| CNN | Convolutional Neural Network（卷积神经网络） | 一种图像分类模型。本项目用它判断"这个候选点是不是真焊点"。 |
| U-Net | — | 一种图像分割模型（输出"每个像素属不属于某类"）。本项目用它把**飞线**从图里抠出来。 |
| 掩膜 | mask | 一张黑白图，白色区域＝模型认为"这里有飞线/有目标"。 |
| 三成员并集 | 3-member union | 用三种不同配置的 U-Net 各出一张掩膜，取"任一为白就算白"的合并结果，减少漏检。 |
| TTA | Test-Time Augmentation（测试时增强） | 对同一张图做几种变换各跑一遍模型，再把结果合并，让结果更稳。 |
| 连通域 | connected component | 图像里连在一起的一整片白色区域（一片飞线、或一片杂质）。 |
| 骨架 | skeleton | 把一片有宽度的线"细化"成一条一像素宽的细线，方便算走向。 |
| 抖动 / 弧弦比 | jitter / arc-to-chord ratio | 判定飞线是否弯曲的两个指标，详见 §5.5。 |
| 阈值 | threshold | 判定用的分界线。比如"抖动 > 7.8088 像素就算弯曲"。 |
| cfg | configuration（配置文件） | 集中存放参数的 JSON/YAML 文件，改参数不用改代码。 |
| 运行目录 | run directory | 每次分析自动新建的文件夹，本次所有产物都在里面，互不覆盖。 |
| GUI | Graphical User Interface（图形界面） | 浏览器里那个可以点的界面。 |
| NG / OK | No Good / OK | 不合格 / 合格。本项目按**判定结果**给产品贴这个标签，不预设。 |

## 一、这个软件做什么

本软件用于**芯片/电路板的出厂质检**：检查焊点是否完好、飞线是否合格。当前版本实现的质检项为"焊点 + 飞线"三项异常（飞线弯曲、飞线断联、焊盘裸露）；软件框架按"可扩展质检项"设计，后续新增质检项不必改动已有流程。

输入：一张或一批板子照片（普通 JPG/PNG）。
输出：**每个产品一条结论——合格 / 不合格**，并给出不合格的原因（弯曲 / 断联 / 裸焊盘），以及一张标好问题位置的结果图。

设计原则（与客户约定的口径）：

1. 报告的主角是**产品**，不是"某类缺陷一共出现几次"。工业现场要知道的是**这一件能不能过**。
2. 缺陷标注只用于**定位**（图上圈出来），不做统计宣传。
3. 判定必须在客户机器上**现场算**：客户没有掩膜，掩膜是软件用模型现场生成的。
4. 只依赖 Python + numpy + opencv + torch(CPU)，不联网、不装额外包、不依赖任何外部服务。

## 五、技术流程（大白话详解）

整体一句话：**先把"可能是飞线的东西"从照片里抠出来，再判断每一块抠出来的东西属于哪一类，最后给每个产品下结论。**

下面按 S1 → S5 的顺序讲。每一步先说"人话目的"，再说"怎么做的"。

### 5.1 为什么要有"候选点"这一步（S1）

**目的**：一张照片里几十万个像素，绝大多数是背景。先粗挑出"像焊点的小圆亮块"（候选点），后面的精细判断只在这些位置做，省时间也减少误判。

**做法**：把图转成灰度，按亮度做二值化（亮的地方＝可能的目标），然后找**连通域**（连在一起的一整片白），对每一片算它的**外接矩形**：如果这一片的最长边够长（超过 20 像素），就把它当一个候选。再对候选做一次"取核心"处理，得到候选点的坐标与半径。

**为什么用"最长边"而不是面积**：面积受亮度影响大；边长的判据更稳定，不容易把背景噪声算进来。

### 5.2 判断候选点是不是真焊点（S2）

**目的**：S1 挑出来的候选里混着灰尘、反光点、板子上的丝印。用一个小型 **CNN（卷积神经网络）**逐张判断"这是不是焊点"。

**做法**：把每个候选点周围裁成一小块图（含该点的局部区域），送入网络，网络输出一个 0–1 之间的分数。分数超过 **0.6** 就算焊点，否则丢弃。

**为什么用 5 个模型投票**：同一个网络用 5 个不同随机种子各训练一次，预测时取 5 个的平均。这叫**集成**——好比 5 个人分别看，多数人的意见比一个人可靠，能压掉偶然的错判。

**标签口径**：只有两类——0 = 不是焊点，1 = 是焊点。（早期还有"标签 2"，后来并入了 1，已废止。）

### 5.3 把飞线从图里抠出来（S3）

**目的**：知道焊点在哪之后，要把**飞线**这条细线的每个像素找出来。这是整个项目最关键的一步，用 **U-Net**（一种图像分割网络）来做。

**做法（三成员并集）**：同一张图，用三种不同"喂法/配置"各跑一遍 U-Net：

1. **TTA 成员**：把原图做几种变换（如不同对比度预处理），各跑一遍再合并；
2. **v13 成员**：一类在"重叠切块"数据上训练出来的权重；
3. **v18 成员**：另一类权重。

得到三张黑白掩膜后，逐像素做**布尔并集**：**只要三个里有任何一个说是飞线，就算飞线**。

**为什么用"并集"而不是"平均"**：这里是"宁可多留、不可漏掉"的场合——漏掉一段飞线会直接导致后来判成断联（错判合格品），多留一点杂块只是多一个待分类的对象，后面会被淘汰掉。所以取并集（偏向召回）。

**一个必须知道的坑**：v13 这份权重的接口内部**不做亮度归一化**，调用方必须先把图像除以 255（把 0–255 的亮度压到 0–1）。忘了除，模型的前景输出会只剩约 7%，看起来"模型失效"。这条已修好并在版本账里记着。

### 5.4 把抠出来的东西分类（S4）

**目的**：并集掩膜是一大堆连在一起的白色块，里面混着飞线、焊盘上的金属、杂质。这一步要把它们整理、切分，并初步分类。

**做法（按顺序）**：

1. **长轴过滤**：最长边小于 20 像素的小碎块直接丢掉（大多是噪声）。
2. **删盘**：在每个焊点位置，按半径 9.92 像素挖掉一个圆——因为焊盘本身也是白的，不挖掉会和飞线连成一片，没法分开计数。
3. **补缺（延长 + 闭运算）**：飞线在接近焊盘的一段常常"淡化"断掉。先把线顺着自己的方向往外延长一小段，再做闭运算（先膨胀后腐蚀）把细缝连上。
   - **延长方向的口径（重要）**：**不查任何焊点**，只顺着这条线自己末段的走向（对末段骨架点做最小二乘拟合得到方向）往外接一个固定长度。
   - **为什么不按"最近的焊点"延长**：附近别的飞线的焊点常常更近，按它延长会横着搭到别人身上，等于人为造假。顺着自己走，正常焊上的线自然就"召回"了自己的焊盘；没焊上的自然召不回——**召不回本身就说明有问题**，这正是我们要的判据。
4. **拆分**：把挖盘后仍然相连的部分按连通域切开，每个小块单独成一条候选飞线。
5. **分类**：数这条线压住了几个焊点，据此分类——

   | 压住焊点数 | 类别 | 含义 |
   |---|---|---|
   | 0 | 噪音 | 不是飞线 |
   | 1 | 断联的飞线 | 只搭上一端 |
   | 2 | 合格（内外圈不同）／焊错（同圈） | 两端都在焊点上 |
   | ≥3 | 干涉 | 多条粘连，需要拆分 |

   判断焊点在"内圈/外圈"是用两个同心圆的半径分界（`RING_K = 94` 像素），这是本项目的固有约定：飞线应当连接**一个外圈焊点与一个内圈焊点**。

**一个曾长期潜伏的 bug（已修）**：这一步与 S5 各自维护一份"焊点表"，一份用斜杠形式（`样例板A`）登记，另一份用连字符形式（`1_NG-1649`）去查 ⇒ 查不到 ⇒ 每一块都被当成"噪音" ⇒ 整段流水线算不出任何结论。修法是"两种形式都登记"，并把这个逻辑统一收进 `core/s_paths.py`。

### 5.5 判定飞线是否弯曲（S5，第 255 步）

**目的**：给每条合格飞线算一个"它有多弯"的数字，超线的判为不合格。

**做法**：

1. 对每条飞线取**骨架**（把有宽度的线细化成一条 1 像素宽的细线）。
2. 在骨架上求**最长测地路径**（两次广度优先搜索得到两端最远的路径）——即"这条线从头到尾的走法"。
3. 剪掉两端属于焊盘范围内的部分（端头只在骨架层剪，不修剪掩膜）。
4. 算两个指标：

   - **抖动（jitter）**：沿着路径走，看它与"两端连成的直线"的最大偏离，单位像素；
   - **弧弦比（arc-chord ratio）**：路径实际长度 ÷ 两端直线距离（直线时为 1，越弯越大）。

5. **判据（当前冻结值）**：抖动 > **7.8088** 像素 **或** 弧弦比 > **1.0062** ⇒ 判为弯曲不合格。
   这两个数是拿 5 块已知合格板取边界得来的，余量为 0（即"刚好卡在合格板的上限"）。

### 5.6 补缺与出图（S5 其余步骤）

S5 一共五步，顺序固定，每一步都能单独出图供人工核对：

| 步骤 | 干什么 | 产出 |
|---|---|---|
| s253 | 补缺（延长 + 闭运算） | 补缺前后的对照图 |
| s255 | 直度判定（§5.5） | `straightness_skeleton.json`（每条线的读数）、`wire_reasons.jsonl`（每条线的原因） |
| s256 | 偏差最大的前 12 条线段面板 | 面板拼图（内部核对） |
| s257 | 全板标号骨架图 | 编号与读数对照（内部核对） |
| s259 | 阶段对照图 | 判定前/判定后（内部核对） |

### 5.7 裸焊盘（断了的焊点）怎么找

**定义**：焊盘裸露、上面没有飞线。

**判据（三条同时满足才算，使用者逐块目视确认过）**：

1. 候选来自"**除杂丢掉的块**"（判定前有掩膜、判定后被剔除的那些）；
2. 该块里**含有焊点的圆心像素**（不是圆盘相交、更不是外接方框相交）；
3. 该块范围内**不存在任何最终飞线掩膜**；且块面积 ≥ 50 像素（滤掉碎渣）。

**曾经做错的三个版本（记下来避免重走）**：

| 版本 | 判据 | 结果 | 错在哪 |
|---|---|---|---|
| A | 焊点圆盘未被任何飞线掩膜盖住 | 12 个 | 断联飞线自己那端的焊点同样盖不住，被误算 |
| B | 判定前后掩膜取差集 + 外接方框相交 | 29 个 | 差集里混进正常加工留下的碎渣，方框判定过宽 |
| C | 圆盘相交 + 面积门限 | 14 个 | 合格板上也报出 6 个，仍偏宽 |
| **V3（现行）** | 见上三条 | **5 个** | 使用者逐块目视确认全部正确 |

### 5.8 出报告（产品视角）

**做法**：按产品聚合三类问题，生成：

- **每张图一张结果图**：标题四行（产品名（原图名）／结论／原因／判据）——排版是"先量字高再逐行排"，不会重叠；
- 图上四色标记 + 图例：

  | 颜色 | 含义 |
  |---|---|
  | 绿 | 合格飞线 |
  | 红 | 弯曲不合格 |
  | 橙 | 断联（线体掩膜取自"判定阶段块"，因为断联的线没有最终飞线掩膜） |
  | 黄（带黑边） | 裸焊盘 |

- **`产品结论.csv`**：一行一个产品（产品 / 原始文件 / 结论 / 原因 / 弯曲 / 断联 / 裸焊盘 / 结果图）。

**板级结论口径**：出现弯曲或断联 ⇒ 该产品不合格；裸焊盘不计入不合格（但单独计数、单独标注）。

## 七、运行前提（必须自备的两样东西）

本软件**不包含**训练好的模型权重与参考数据，它们属于使用方的数据资产：

| 需要自备 | 作用 | 缺了会怎样 |
|---|---|---|
| **模型权重**（`models/cnn/*.pt`＝5 种子 × 5 折，`models/unet/*.pt`＝TTA 成员 + v13 + v18） | CNN 判焊点、U-Net 出飞线掩膜 | S2 起就没有输出，流水线停在候选点之后 |
| **参考数据 `refs/`**（`refs/annot/` 标注归档 + `refs/solder_table.json` + `refs/boards.json`） | S4 的参考流程按它取"归档掩膜"与焊点表 | 能跑完 S1–S3，**S4 报 `IndexError`**，后续无结果 |

**填写位置**：权重文件名写在 `cfg/default.json` 的 `s2_cnn.weights_dir`（默认 `models/cnn`）与 `s3_unet_mask.weights` 里；`refs/` 路径由 `core/s_paths.py` 与各步骤从软件根目录解析，替换目录内容即可，不需要改代码。

**参考数据怎么来**：两种方式——
1. **真实标注**（推荐用于正式验收）：用你自己的样品图与人工逐像素标注构成 `refs/annot/`，焊点表用 S1+S2 的产出；
2. **占位生成**（用于先把流程跑通）：先用 `run_pipeline.py` 跑一次，再执行
   `python tools/make_placeholder_refs.py --src <图片目录> --out refs --from-run <运行目录>`，
   掩膜由软件自身的板面分割生成、焊点表取自那次运行。
   **实测**：10 张样品用方式 2 ⇒ 全链计数与基准一致（读数 117 ｜ 弯曲 4 ｜ 断联 7 ｜ 裸焊盘 5）。
   注意：脚本会拒绝"无焊点表的空表"生成（空表会导致整批被误判为裸焊盘，实测读数 0 / 裸焊盘 123）。

**验收基准**：10 张样品跑全流程应得 **读数 117 ｜ 弯曲 4 ｜ 断联 7 ｜ 裸焊盘 5**；数字不同说明权重或参数与基准版本不一致。

## 八、一句话总结

这套芯片质检软件把"抠焊点与飞线 → 分类 → 判弯 → 找裸露焊盘 → 出逐产品结论"连成一条命令；它的价值不在于生成了多少中间图，而在于**对每一件产品给出一个可追溯的合格/不合格结论**，并且这个结论可以在客户的机器上、离线、用同样的判据重复算出来。

### 5.9 实现细节（API 级）与"新缺陷出现时怎么重训"

这一节回应三个常被问到的问题：**图片进来后到底被哪些函数处理了、每一处提取到了什么信息、模型是怎么训出来的（以及客户遇到新缺陷时怎么自己重训）。**

#### (1) S1 候选点：具体调了哪些 API、得到什么

| 顺序 | 调用 | 作用 | 得到的量 |
|---|---|---|---|
| 1 | `core.mask.read_gray(path)` → `cv2.imread(..., IMREAD_GRAYSCALE)` | 读图为单通道灰度 | 灰度矩阵 `g`（0–255） |
| 2 | `core.vendor.seg.module_mask(g, sigma, kclose, kopen, area_frac)` | 找"芯片本体"所在区域 | 芯片区域掩膜 |
| 3 | ↳ `cv2.GaussianBlur`（σ 由 cfg 给） | 先去噪，避免亮点噪声被当成目标 | 平滑图 |
| 4 | ↳ `cv2.threshold(..., THRESH_BINARY + THRESH_OTSU)` | 自动选阈值二值化（Otsu：按灰度直方图自动找分界，不用人工定阈值） | 二值图 |
| 5 | ↳ `cv2.morphologyEx(MORPH_CLOSE)` 再 `MORPH_OPEN` | 闭运算补小孔、开运算去毛刺 | 干净的区域块 |
| 6 | ↳ `cv2.findContours` + 按 `contourArea` 排序 | 取最大的轮廓（芯片本体），并保留面积 ≥ `area_frac × 最大面积` 的轮廓 | 芯片区域轮廓 |
| 7 | `core.s1_candidates.run_board(path, cfg, name)` | 在芯片区域里挑"像焊座/焊点"的小块 | 候选点列表 `rows`（每个含 `x, y, r`）、以及供后续使用的灰度图 |

要点：**候选点只是"粗挑"**，判据是最长边门限（cfg 中的 `MIN_AXIS = 20` 像素）。真正"是不是焊点"由下一步 CNN 决定。

#### (2) S2 CNN：吃什么、怎么训、怎么判

- **原料（训练数据）**：以候选点为中心、边长 **48×48 像素**的小方块（`core/patches.py::crop_at`，`S = 48`，与训练时严格一致，不许改）。标签只有两类：**0 = 不是焊点、1 = 是焊点**，来自人工分类目录（本项目当前规模量级：0 类约千余、1 类约二百余）。
- **送入格式**：`X[i, 0] = (crop - mu) / sd`，即**逐块标准化**（减均值除标准差）。这一步很关键：不做标准化，亮度差异会被网络当成特征。
- **网络与集成**：5 个不同随机种子的同结构小 CNN，各自输出 0–1 分数；**取 5 个的平均**，平均分 ≥ cfg 里 `s2_cnn.thr`（当前 0.6）判为焊点。
- **为什么集成**：单模型对边界样本（半明半暗的焊点）波动大，5 模型平均能显著降低这种随机错判。

#### (3) S3 U-Net：为什么必须有人工标签、为什么切碎、为什么不止一个

- **为什么需要人工标签**：U-Net 是**语义分割**模型——它要输出"每个像素属不属于飞线"。这类训练不是"告诉它这张图里有没有飞线"，而是需要**逐像素的答案**（人工在图上描出飞线区域做成黑白掩膜）。没有这种逐像素标签，网络学不会"哪里到哪里算飞线"。
- **为什么要把图切碎再拼回**：训练时用 **192×192** 的小块（本项目按 **步长 96、即 50% 重叠**滑窗切块）。原因有三：① 显存/内存有限，整图一次进网络吃不消；② 小块使得网络见到的都是"局部纹理"，泛化更好；③ **重叠**能保证飞线跨块时不会在接缝处被切断。预测时同样切块，再**按每像素被覆盖的次数求平均**拼回原尺寸，接缝因此无痕。
- **为什么不止一个 U-Net**：不同"配方"的网络犯的错不一样——换前处理、换损失函数、换数据增强，错误就互相错开。本项目保留三组成员：
  1. **TTA 成员**：cfg 列表里的一批单通道模型 × **4 种视图**（对同一张图做几种轻微变换各跑一次再平均），最后与其它成员合并；
  2. **v13 成员**：在"重叠切块 + 原始灰度"数据上训练的一套权重；
  3. **v18 成员**：另一套配方（不同的卷积/归一化与损失组合）训练出来的权重。
  三组各出一张黑白掩膜，再取**布尔并集**（任一为白即白）——偏向"宁可多留，不可漏掉"。
- **各成员的前处理**（决定"网络看到什么"，写错就等于喂错料）：

  | 模式 | 代码 | 做什么 | 为什么 |
  |---|---|---|---|
  | `raw` | `g / 255.0` | 原图直接归一化到 0–1 | 不做假设，保留原始亮度分布 |
  | `pct` | `norm_pct(g) / 255.0`：取 2% 与 98% 分位做线性拉伸 | 把过暗/过亮两端压掉 | 应对曝光不均、批次亮度差异 |
  | `clahe` | `CLAHE2.apply(g) / 255.0` | 自适应直方图均衡 | 应对局部光照不均（芯片边缘偏暗） |

  **接口陷阱（已修，务必留意）**：`v13` 那份权重的推理函数**内部不做归一化**，调用方必须传 `原图/255`。忘了除，前景输出只剩约 7%，看起来像"模型坏了"。
- **为什么进网络前要先找"芯片区域"**：背景（桌面、夹具）会被网络误当飞线。先在 S1/S4 阶段限定芯片范围，能显著压低误检。

#### (4) 客户遇到新缺陷、想提高精度时，怎么重训

训练接口**特意保留在代码里**（`train/` 目录下的训练脚本），但**默认不启用**，交付版只做推理。重训流程：

1. **攒数据**：把新样品的图片放入数据集目录，并按"图片 → 对应掩膜"成对准备。掩膜需要人工描（或半自动生成后人工修），这是 U-Net 训练的必要成本。
2. **重训**：用 `train/` 里保留的训练脚本训练一份新权重（脚本已去掉写死的绝对路径：`CHIP_ROOT`／`CHIP_DATA`／`CHIP_PY` 三个环境变量可分别指定软件根目录、训练数据根目录与解释器，默认值见 `train/README.md`）（脚本会按数据切分训练/验证，输出 `model_*.pt`）。
   - **注意**：训练脚本写权重时请务必带**版本标记（tag）**，否则会覆盖已有权重——这是已知隐患，交付前应加防覆盖。
3. **登记**：把新权重文件放进 `models/unet/`，并在 `cfg/default.json` 的 `s3_unet_mask.weights` 里把它加入对应成员（或新增一个成员）。
4. **验收**：跑 10 张基准样品，四个数字必须与基线一致（见 §六：验收标准）；**如果数字变了，说明新权重改变了既有判定，需要人工逐项核对后再决定是否采用**。
5. **回滚**：权重与 cfg 都有备份，替换文件即可回到旧版本。

> 一句话：**飞线（和以后新增的质检项）出现新形态时，软件本身不用改，改的是"权重 + cfg 登记 + 基准验收"这三件事。**

### 5.10 前处理 API 明细（客户最关心的"到底调了什么、参数是多少"）

#### (1) CNN 分支（S2）——从像素块到"是/不是焊点"

| 步骤 | 具体 API / 表达式 | 参数 | 作用原理 |
|---|---|---|---|
| 读图 | `cv2.imread(path, cv2.IMREAD_GRAYSCALE)` | — | 转单通道灰度，避免彩色通道带来无关差异 |
| 取块 | `core.patches.crop_at(g, x, y, s=48)` | `s = 48`（与训练严格一致） | 以候选点为中心裁 48×48 的小方块，只留局部上下文 |
| 标准化 | `mu = g.mean()`；`sd = g.std() + 1e-6`；`X = (crop.astype(np.float32) - mu) / sd` | 逐块各算各的 | **逐块标准化**：把每块的亮度／对比度归一到同一尺度，否则网络会把"整体偏亮"当成特征；`+1e-6` 防止全黑块除零 |
| 推理 | 5 个权重各跑一遍，`P = 各模型输出的堆叠` | 5 个随机种子的同结构小 CNN | 集成投票，压掉边界样本上的随机错判 |
| 汇总 | `mean = P.mean(axis=0)`；`判为焊点 = mean >= cfg.s2_cnn.thr` | `thr = 0.6` | 5 个分数的平均过阈值 |

#### (2) U-Net 分支（S3）——四种前处理模式（写在 `cfg.default.json` 的 `weights` 里）

| 模式 | 实现 | 等价的 API/表达式 | 原理与适用 |
|---|---|---|---|
| `raw` | `unet_tta.prep(g,"raw")` | `g.astype(np.float32) / 255.0` | 原图线性归一到 0–1；不做亮度假设，最"忠实" |
| `pct` | `unet_tta.prep(g,"pct")` → `norm_pct` | `lo,hi = np.percentile(g,2), np.percentile(g,98)`；`np.clip((g-lo)*255.0/max(1e-6,hi-lo), 0, 255) / 255` | 取 2%–98% 分位做**线性拉伸**：把过暗/过亮两端截掉再拉开对比度，抗曝光不均 |
| `clahe` | `unet_tta.prep(g,"clahe")` | `CLAHE2 = cv2.createCLAHE(2.0, (8, 8))`；`CLAHE2.apply(g) / 255.0` | **自适应直方图均衡**（clipLimit=2.0，网格 8×8）：分小块各自均衡，抗**局部**光照不均（芯片边缘偏暗） |
| `zscore` | 在 `unet_v18` 的**网络前端内部**做 | 前端对输入做 z-score 标准化（+ 残差标准化 + sigmoid 输出头） | 把标准化和激活搬进网络内部，网络自己学"怎么归一" |

三成员实际配置（`cfg.default.json` → `s3_unet_mask`）：

| 成员 | 权重文件 | 前处理模式 |
|---|---|---|
| TTA（5 个单通道模型 × **4 视图**） | `unet_v3_unet8.pt`（raw）、`unet_v6_A_pct.pt`（pct）、`unet_v6_B_clahe.pt`（clahe）、`unet_v10_cldice3.pt`（pct）、`unet_v11_raw_cldice.pt`（raw） | 按上表各自模式 |
| v13 | `unet_v13_raw_overlap50.pt` | `raw`（**调用方必须传"原图/255"**） |
| v18 | `unet_v18_conv3_sig_zscore.pt` | `zscore`（网络内部处理） |

**4 视图（Test-Time Augmentation）**：`cfg` 里的 `views = ["id", "fliplr", "flipud", "rot180"]`——原图、左右翻、上下翻、转 180°，各推理一次再合并；`tta_views = 4`。

#### (3) 切块与拼回（U-Net 的输入组织）

| 项目 | 值 / 实现 | 说明 |
|---|---|---|
| 块尺寸 | `C = 192`（192×192） | 与训练一致 |
| 步长 | `stride = 96` ⇒ **50% 重叠** | 保证飞线跨块不被接缝切断 |
| 累加 | `acc = np.zeros((h,w), np.float32)`；`cnt = np.zeros((h,w), np.float32)`；逐块 `acc[...] += p`；`cnt[...] += 1` | 每个像素被覆盖几次就累加几次 |
| 拼回 | `(acc / np.maximum(1.0, cnt)) > thr` | 按**覆盖次数求平均**再二值化：重叠区因多次预测取均值而平滑，接缝无痕 |
| 合并 | 三成员掩膜逐像素**布尔并集** | 偏向召回：宁可多留杂块（后续会被淘汰），不可漏掉一段飞线 |
